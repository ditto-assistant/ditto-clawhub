# Review Comments (background agent)

Autonomously handle PR review comments. Clones the repo into an **isolated copy** so the current working tree is never touched.

**User Input**: $ARGUMENTS

Designed to run via the `Agent` tool with `run_in_background: true`.

---

## Overview

End-to-end review-feedback resolution:

1. Clone the target Ditto repo into a fresh directory **one level above** the current cwd
2. Initialize Graphite and check out the target branch
3. Fetch all unresolved review comments via the GitHub REST API
4. Read referenced source files, understand each comment
5. Apply fixes
6. Amend the branch via `gt modify` and `gt submit --no-edit`
7. Resolve all review threads via the GraphQL API
8. Update PR title/body if scope changed
9. Report

---

## Execution Steps

### 1. Parse Input

Extract:
- `PR_NUMBER` (from URL or branch lookup)
- `BRANCH` (head ref)
- `REPO` (default: detect from PR URL, else ask)

```bash
# From PR URL
PR_NUMBER=$(echo "$ARG" | grep -oE 'pull/[0-9]+' | grep -oE '[0-9]+')
REPO=$(echo "$ARG" | grep -oE 'ditto-assistant/[^/]+' | cut -d/ -f2)

# From PR number on current branch
PR_NUMBER=$(gh pr view --json number -q .number)
REPO=$(gh repo view --json name -q .name)

# Or from a bare branch name
PR_NUMBER=$(gh pr list --head "$BRANCH" --json number -q '.[0].number')

BRANCH=$(gh pr view "$PR_NUMBER" --repo "ditto-assistant/$REPO" --json headRefName -q .headRefName)
```

If `REPO` is ambiguous, ask the user.

### 2. Clone Fresh Copy

Clone **one level above** the source repo so we don't collide with the user's worktrees:

```bash
SRC_DIR="${SRC_DIR:-$(cd .. && pwd)/$REPO}"
CLONE_DIR="${TMPDIR:-/tmp}/$REPO-review-pr-$PR_NUMBER"

rm -rf "$CLONE_DIR"
git clone "git@github.com:ditto-assistant/$REPO.git" "$CLONE_DIR"
cd "$CLONE_DIR"
```

If clone is slow, you can clone from a local source as a shortcut (uses local objects). Set `SRC_DIR` to the source checkout path when auto-detection does not match your layout:

```bash
if [ -d "$SRC_DIR/.git" ]; then
  git clone --reference "$SRC_DIR" --dissociate "git@github.com:ditto-assistant/$REPO.git" "$CLONE_DIR"
fi
```

### 3. Initialize Graphite & Check Out

```bash
gt init --trunk main
gt get "$BRANCH"
```

If the branch arrives "frozen," unfreeze:
```bash
gt unfreeze
```

See [`graphite`](../graphite/SKILL.md) for full reference.

### 4. Fetch Review Comments

REST API for inline comments:

```bash
gh api repos/ditto-assistant/$REPO/pulls/$PR_NUMBER/comments --paginate \
  --jq '.[] | {id, path, line: (.line // .original_line), body: (.body | split("\n")[0:3] | join(" / "))}'
```

For each comment, capture:
- `path` — file to change
- `line` / `original_line` — location
- `body` — the reviewer's feedback (often includes a ` ```suggestion ` block — pay close attention)

Also fetch top-level review comments (not tied to a line):

```bash
gh api repos/ditto-assistant/$REPO/pulls/$PR_NUMBER/reviews --paginate \
  --jq '.[] | select(.state != "APPROVED") | {id, state, body}'
```

### 5. Understand & Fix

For every comment:

1. **Read** the referenced file at the indicated lines
2. **Understand** what the reviewer is asking — `suggestion` blocks usually mean "apply this verbatim"
3. **Apply** the fix with minimal, targeted edits (use the `Edit` tool, not full rewrites)
4. If a comment says "same issue in file X" or "applies to all callers," fix every location

For Ditto-specific surfaces:
- **sqlc-generated code** in `pkg/database/turso/` — never edit by hand. If a reviewer points there, edit the source `.sql` query in `pkg/database/turso/query.sql` and run `just generate` instead.
- **templ-generated code** (`*.templ.go`) — same: edit the `.templ` source, run `just generate`.
- **Frontend types** generated by zod schemas — edit the schema, not the generated type.

### 6. Modify & Submit

```bash
gt modify                       # amend HEAD, keep commit message, restack descendants
gt submit --no-edit             # force-push
```

If `gt submit` fails with a restack warning:
```bash
gt restack
gt submit --no-edit
```

If new commit message is warranted (rare — only when the scope materially changed):
```bash
gt modify -m "<new commit/PR title>"
```

### 7. Resolve Review Threads

Fetch thread IDs:

```bash
gh api graphql -f query='
query {
  repository(owner: "ditto-assistant", name: "'"$REPO"'") {
    pullRequest(number: '"$PR_NUMBER"') {
      reviewThreads(first: 100) {
        pageInfo { hasNextPage endCursor }
        nodes { id isResolved comments(first: 1) { nodes { body } } }
      }
    }
  }
}'
```

Paginate with `after: "<endCursor>"` if needed.

Resolve each unresolved thread you addressed:

```bash
gh api graphql -f query='
mutation { resolveReviewThread(input: {threadId: "THREAD_ID"}) { thread { id isResolved } } }'
```

Only resolve threads whose feedback you actually addressed. If something is informational/not-actionable, still resolve it after acknowledging. If something is **ambiguous or needs design judgment**, leave the thread open and surface it to the user.

### 8. Update PR Title & Description

If the fixes changed the PR's scope (renames, removed/added behavior, new files):

```bash
gh pr view $PR_NUMBER --repo ditto-assistant/$REPO --json title,body
gh pr edit $PR_NUMBER --repo ditto-assistant/$REPO --title "new title" --body "new body"
```

Use the body shape from the [`github`](../github/SKILL.md) skill. If title/description still accurate, skip.

### 9. Report

Output a short summary:

- PR URL
- Number of comments addressed (and how many were left open + why)
- Files changed (`git diff --stat origin/main..HEAD`)
- Whether title/description were updated
- Confirmation threads resolved

---

## Notes

- This is designed to run as a **background agent** via the `Agent` tool with `run_in_background: true`. The fresh clone ensures zero interference with the user's worktree.
- The clone directory under `${TMPDIR:-/tmp}` is disposable — the user can delete it after the PR merges. The skill does NOT clean up automatically.
- If a comment requires **architectural judgment** or is ambiguous, **do NOT guess** — leave the thread open and surface it in the final report.
- Never use `--no-verify` on commits, even if pre-commit hooks fail. Fix the underlying issue.
- For backend PRs that touch generated code: run `just generate` and stage the result before `gt modify`.
